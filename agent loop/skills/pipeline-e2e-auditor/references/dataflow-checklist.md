# 前后端数据传递检查清单

## 每个接口的检查维度

### 请求方向：前端 → 后端
- [ ] 前端发送的每个字段，后端接口定义中是否存在对应参数
- [ ] 字段类型是否一致（前端发 string "3"，后端期望 int 3）
- [ ] 嵌套对象的 key 名是否一致（前端用 camelCase，后端可能用 snake_case）
- [ ] 必填字段是否在前端每次请求中都携带
- [ ] 前端是否发了后端已废弃的字段（多余字段，后端静默忽略）

### 响应方向：后端 → 前端
- [ ] 后端返回的每个字段，前端是否实际使用（grep 前端源码确认引用）
- [ ] 字段类型是否匹配（后端返回 null 时前端是否做了空值处理）
- [ ] 列表字段在后端返回 [] vs null 时，前端的 .map()/.length 是否安全
- [ ] 后端新增的字段前端是否漏了展示
- [ ] 嵌套结构的层级变化（后端某天改了嵌套深度，前端还在按旧路径取数据）

### 边界情况
- [ ] 空列表时接口返回什么（[] / null / 不返回该字段）
- [ ] 单条记录 vs 列表 —— 是否有时返回对象有时返回数组
- [ ] 分页参数：page/size/total 的字段名前后端是否对齐

## 检查方法

1. 从阶段 1 截获的 Network 请求中，逐一提取 {url, method, request_payload, response_body}
2. 找到后端对应的路由处理函数，提取参数定义和返回结构
3. 用 `scripts/diff_schemas.py` 对每个接口生成字段级对比
4. 对每个差异点：判断是前端多发了、后端少返了、还是字段名不一致

## 常见数据传递 bug 信号

- 前端 Network 面板里请求 payload 中出现 undefined
- 后端日志中参数值为空但前端传了值（字段名不匹配）
- 前端页面显示"加载失败"但后端返回 200（response 结构不匹配）
- 翻页后数据不变（page 参数未正确传递）
- 某字段在所有请求中都为 null（后端未返回或前端取了错误的 key）

## 不做什么

- 不假设字段名前后端一致——必须逐字段核对源码
- 不看 200 OK 就认为没问题——HTTP 状态码和数据正确性是两层
- 不因为"之前能跑通"就跳过检查——字段可能被逐渐改坏
